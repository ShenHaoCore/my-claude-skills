# TAPD 开发任务规则

来源：《TAPD操作指导和规范要求》V1.0（2026-09-14）。这里只保留开发人员提交 Task 所需的规则。

> ⚠️ 本 skill 于 2026-10-14 做过一次环境适配：早前版本源自 Codex 环境，工具名已按当前
> 官方 `tapd` 连接器（`mcp__tapd__*`）全部替换。创建工作项的流程已移交 `tapd-create-guard`，
> 本 skill 只负责状态推进与工时登记。详见 `SKILL.md` 开头的分工说明。

## 层级和关联

- Epic 表示项目/系统归属，Feature 表示版本，Story 表示需求，Task 表示执行任务。
- Task 必须关联 Story；开发或测试阶段应创建并关联实际执行任务。
- 任务计划时间由责任人手动填写，实际时间由状态流转自动写入。

## 开发人员职责

- 在 Story 上填写开发人员、计划开发开始时间和计划提测时间。
- 按流程推进 Story：`需求评审通过 → 开发中 → 已提测`。
- 创建 Task、推进 Task 状态并填写实际工时。

## Task 创建字段

规范要求以下字段必填：

| 字段 | 要求 |
| --- | --- |
| 父需求 | 必须选择并关联 Story |
| 任务类型 | 使用当前项目字段配置中名称为“任务”的选项 |
| 优先级 | 使用当前项目实际可选值 |
| 处理人 | 必须指定 TAPD 用户 |
| 预计开始 | 日期 |
| 预计结束 | 日期 |
| 预估工时 | 数字，单位为小时 |

## Task 状态和工时

- 状态：`未开始 → 进行中 → 已完成`，对应 API 值 `open → progressing → done`。
- 将任务转为“进行中”时必须有处理人。
- 完成工时按小时记录，一般每天按 8 小时估算；单条任务不能超过 24 小时。
- 将任务转为“已完成”时，按实际情况手动填写工时或选择自动补足剩余工时。

### 使用约定（非 V1.0 规范原文，可按所在团队调整）

| 约定 | 内容 |
| --- | --- |
| 单日上限 | 同一登记人同一花费日期**合计 >12h** 须醒目提示「请与主管确认工时的合理性」，建议减少或分摊；用户坚持才放行。上限可用 `timesheet_guard.py --limit-hours` 调整 |
| 登记后复查 | 写入后**重新拉当天全空间工时**再算一次（他人可能同天登记），不得跳过 |
| 分摊规则 | 按 **8h/天** 拆分；跳过周六日，且**必须核对法定调休**——调休上班的周末算工作日，假期内的工作日算休息；节假日安排以用户提供的日历为准 |

## 例外口径

- 只要是 Story 下需要执行、跟踪或记录工时的工作，都应创建 Task；很小且同类型的工作可以合并，避免拆得过碎。
- 已有对应 Task 时，直接在原 Task 记录处理情况和工时；没有对应 Task 且产生实际代码变更或需要纳入统计时，创建简短 Task。
- 发现需求理解错误时先暂停并与产品确认；如果变成新的需求范围，应新建 Story，不要继续扩大原 Task。
- Story 已上线后发现问题，应新建并关联 Bug 或新 Story，不要把原上线 Story 当作新的开发任务容器。
